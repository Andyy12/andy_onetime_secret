# CLAUDE.md - GoDatalize Secretos Developer & AI Assistant Guide

Guide for developers and AI agents working on **GoDatalize Secretos**, a
customized fork of [Onetime Secret](https://github.com/onetimesecret/onetimesecret).
Read `AGENTS.md` first: its rules (test lanes, review conventions) take
precedence over this file.

---

## 1. Project Overview

**GoDatalize Secretos** shares sensitive information (passwords, keys, `.env`
blocks) through links that work once and expire automatically.

- **Company site**: [https://www.godatalize.com](https://www.godatalize.com)
- **Brand pack**: `public/branding/godatalize/` (baked over the default pack at Docker build, `BRAND_PACK=godatalize`)
- **Deploy**: Docker image built from `Dockerfile` and run on Easypanel
- **Upstream**: remote `upstream` → `onetimesecret/onetimesecret`. Keep fork changes small and isolated so upstream merges stay easy.

---

## 2. Technology Stack

### Frontend
- Vue 3.5 (`<script setup lang="ts">`), Pinia, vue-router
- Tailwind CSS 4 (`@tailwindcss/vite`), dark mode via `dark:*`
- vue-i18n 11; sources in `locales/content/{locale}/*.json`, merged to `generated/locales/*.json`
- Vite 8 (Rolldown), **single JS bundle** (no code splitting, for CSP nonces)
- Vitest + `@vue/test-utils`
- Headless UI (`@headlessui/vue`) for menus and dialogs
- Icons: `OIcon` renders `<use href="#collection-name">` from an SVG sprite — only icons in the sprite exist; use inline SVG for anything else

### Backend
- Ruby 3.4, Rack, **Roda + Otto** routing, Rodauth (full auth mode), Puma
- Redis via Familia (secrets, sessions, rate limits); Sequel (SQLite/Postgres) for full-auth accounts
- Mail: ERB templates in `lib/onetime/mail/templates/`

## 3. Core Repository Invariants

1. **Session keys** are strings, never symbols.
2. **Timestamps** are UTC; convert only at the display edge.
3. **Brand links** point to `https://www.godatalize.com` (constants `GODATALIZE_WEBSITE_URL` / `GODATALIZE_WEBSITE_LABEL` in `src/shared/constants/brand.ts`). Footers show `www.godatalize.com`; the build version lives in the link's tooltip.
4. **SessionSidecar**: short-TTL delete-on-read keys; expiry is privacy, not data loss.
5. **Ruby tests only through `tests/lanes/run`** — never `rspec`/`rake spec` directly.
6. **i18n syntax**: `@`, `{`, `}` and `|` are message syntax in vue-i18n. Escape literals as `{'@'}`. Development only *warns* on bad syntax; **production throws and blanks the page**. `src/tests/i18n/message-syntax.spec.ts` guards this.

## 4. Fork Features (where they live)

### 4.1 Password generator
- `src/shared/composables/usePasswordGenerator.ts` — `crypto.getRandomValues` with rejection sampling; length clamped to **6–128** in code (UI offers 6–64, constants `GENERATOR_MIN_LENGTH` / `GENERATOR_MAX_LENGTH`).
- Remembers settings per browser (`loadGeneratorPrefs` / `saveGeneratorPrefs`, key `godatalize.passwordGenerator.v1`). Never stores the password. Reads are validated.
- `src/shared/components/forms/PasswordGeneratorConfig.vue` — preview, re-roll, copy, 4-segment meter, length slider + number input, character-set checkboxes. Emits `update:password` and `change`.
- Used by `SecretForm.vue` and `WorkspaceSecretForm.vue` ("generate password" mode).

### 4.2 Quick templates (dropdown)
- Catalog: `src/apps/secret/components/form/secretTemplates.ts` (8 templates: credentials, email, database, env, api, ssh, wifi, vpn).
  - `fields` templates use translated labels (`web.templates.fields.*`); `lines` templates stay literal (`DB_HOST=`…).
  - `insertTemplate()` appends after a blank line when the textarea has text; never overwrites. Caret lands at the end of the first line.
- UI: Headless UI `Menu` in `SecretContentInputArea.vue`.

### 4.3 Receipt page (`src/apps/secret/components/receipt/`)
- `SecretLink.vue` — link, QR button, copy, cURL snippet (`curl -s "<share_url>"`; a GET shows the confirmation page and does **not** burn the secret).
- `ShareMessageActions.vue` — live **countdown** to `record.expiration` and **"Copy message"** + WhatsApp / email shortcuts. Message built by `shareMessage.ts`; it says a passphrase comes through another channel and never includes it.
- `src/shared/composables/useCountdown.ts` — ticks every second in the last hour, every 30 s otherwise; units formatted with `Intl.NumberFormat` (no translation keys).
- `src/shared/components/ui/SecretQrModal.vue` — QR as PNG data URL (`QRCode.toDataURL`), generated in the browser; download button.

### 4.4 Reveal page
- `canonical/` and `branded/SecretDisplayCase.vue` — `useDecryptReveal` one-shot scramble animation (display only; copy uses the real value), "burned" notice.
- `SecretConfirmationForm.vue` — explicit "Reveal secret" button and one-time warning. (No strength meter here: the recipient types a passphrase they did not choose.)

### 4.5 Incoming secrets ("send us a secret")
- Upstream feature at `/incoming`, enabled with `INCOMING_ENABLED=true` + `INCOMING_RECIPIENT_N=email[,name]` (up to 4). Rate limited per IP and per recipient by default.
- Fork addition: bootstrap flag `features.incoming` (`apps/web/core/views/serializers/config_serializer.rb#build_feature_flags`, schema `src/schemas/contracts/bootstrap.ts`) drives `src/apps/secret/components/conceal/IncomingCallout.vue` on the homepage: a "send us a secret" box for visitors, plus "copy request link" for signed-in team members.

### 4.6 Reveal notification
- Upstream: account preference `cust.notify_on_reveal`; V3 reveal (`apps/api/v3/logic/secrets.rb#notify_owner_of_reveal`) enqueues the `secret_revealed` email.
- Fork addition: `src/shared/components/forms/RevealNotifyToggle.vue` — the same switch, on the create form for fully authenticated users. It is **account-wide**, not per secret.

### 4.7 Error monitoring (Sentry)
- Already integrated (backend, frontend `src/plugins/core/enableDiagnostics.ts`, workers). Enable with `DIAGNOSTICS_ENABLED=true` + `SENTRY_DSN`. Default `SENTRY_SAMPLE_RATE` is `0.10` (sends 1 in 10 errors) — set `1.0` for small installs.

### 4.8 Emails
- Spanish copy and GoDatalize styling in `lib/onetime/mail/templates/*.html.erb`; user values always escaped with `h()`. Logo: `email_logo_url` in `lib/onetime/mail/views/base.rb`.

## 5. Workflows & Commands

### 5.1 Windows / PowerShell
- `git` may not be on PATH; GitHub Desktop bundles one at `%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`. Pushing needs the user's GitHub auth (use GitHub Desktop → Push).
- Run pnpm through npx when the `.ps1` shim is blocked: `cmd.exe /c "npx pnpm install"`.

### 5.2 Tests
```powershell
cmd.exe /c "npx pnpm vitest run src/tests/i18n/message-syntax.spec.ts"
cmd.exe /c "npx pnpm vitest run src/tests/composables src/tests/components"
```
Ruby: `tests/lanes/run unit` (see `tests/lanes/README.md`).

### 5.3 i18n workflow
1. Edit `locales/content/en/*.json` (source, `content_hash`) and `locales/content/es/*.json` (`source_hash` = the en hash).
2. Hash = first 8 hex chars of SHA-256 of the trimmed English text. `python locales/scripts/i18n content hashes --apply` computes it.
3. `pnpm run build` runs `prebuild` → `locales:sync`, which regenerates `generated/locales/`. Never edit generated files.
4. Run `message-syntax.spec.ts` after editing translations.

### 5.4 Deploy (Easypanel)
- Commit + push to `main`, then redeploy. The Docker build compiles locales and the frontend.
- Without `JOBS_ENABLED`, the web process sends email itself (no RabbitMQ worker needed).
- Env reference: `.env.example`, full list in `etc/defaults/config.defaults.yaml`.

## 6. Conventions
- `<script setup lang="ts">`, composables for stateful logic, pure helpers in `.ts` files next to the component so they can be unit-tested.
- No hard-coded user-facing text: every string goes through `t()` with en + es keys.
- Accessibility: labels on icon buttons, `role="switch"` + `aria-checked` on toggles.
- `localStorage` only for per-browser conveniences, always inside `try/catch`.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`); descriptive messages.
